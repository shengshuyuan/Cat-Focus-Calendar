# FoloToy AI Passport 发布工具

从创作者当前项目准备可信的社区投稿，然后使用随附的发布脚本完成授权和上传。

## 工作流程

1. 检查项目 README、文档、源码、Git 远端、构建配置和现有产物。确认唯一一个从 `0x0` 烧写的 ESP 合并 `.bin` 镜像；有多个候选时不得猜测。
2. 按下面的“先展示玩法”规则准备中英文标题和描述。缺少一种语言时翻译并完善已有文案；如果没有可用描述，就根据 README、文档、截图、演示媒体、界面文字和可观察的交互流程起草简洁且有事实依据的文案。任何不确定内容都要明确标注，不得虚构功能。
3. 如果存在 Git 远端，从 Git 远端解析当前源码仓库。支持 GitHub、Gitee、GitLab、Codeberg 和其他公开可访问的 HTTPS Git 仓库页面。SSH 远端明确对应时可转换为 HTTPS 项目页面。没有公开仓库时，仓库 URL 不是必须项，不要因此阻塞投稿。
4. 要求创作者通过 USB 串口连接设备，并在准备或提交封面前取得新的运行时屏幕捕获。运行 `python3 scripts/publisher.py capture-screen --list-ports`，让创作者确认设备端口，再运行 `python3 scripts/publisher.py capture-screen --port <port> --output <screen.png>`。该操作读取显示帧缓冲，不拍摄实体设备，也不要求成品封面出现设备。成功捕获会创建 PNG 及相邻的 `.fap-capture.json` 回执。端口不可用、创作者未确认端口、固件未实现 `FAP_SCREENSHOT_V1` 或捕获失败时不得继续，并说明固件必须先加入随附协议。绝不刷写固件、重置设备或在多个端口中猜测。使用捕获画面前必须检查其中没有设备 KEY、密码、私有令牌、个人数据或其他秘密。参见 [`references/serial-screenshot.md`](references/serial-screenshot.md)。
5. 选择或准备严格 3:4 竖向比例的 JPEG、PNG 或 WebP 封面；新封面优先使用 `1152x1536`。把运行时屏幕捕获当作真实玩法的证据，而不是要求封面复刻实体设备。封面应以玩法为主：如果更有表现力，应优先展示玩法世界、动作、角色、核心交互或界面。不必出现实体设备，也不得为了宣传硬件而强行加入。只有在构图确实包含 AI Passport 时，才使用随附的 [`references/ai-passport-device-reference.png`](references/ai-passport-device-reference.png) 作为权威实体产品参考，并保留透明竖向外壳、居中的挂绳孔、上方屏幕、屏幕旁的圆形控制键、下方电池块和带槽下扬声器。任何可见设备屏幕都必须明亮、清晰、彩色且有视觉作用；应展示实际玩法界面或具有代表性的内容，避免黑屏、空白、昏暗、关机或不可读画面。所有表述都必须有项目事实依据。
6. 在提出投稿前运行 `python3 scripts/publisher.py validate --firmware <file> --cover <file> --screen-capture <screen.png>`。命令会拒绝缺失、被修改或过期的串口捕获回执。
7. 如果尚未授权，运行 `python3 scripts/publisher.py authorize`。脚本会自动打开官方创作者页面。引导创作者在页面注册或登录并批准显示的代码。绝不要索要、接收或保存创作者密码。
8. 在 `submit` 中使用可用的 `--source-url` 和 `--screen-capture <screen.png>`，不要带 `--confirmed`，先打印准确预览。向用户展示每个字段、固件、封面和捕获文件的路径、大小与 SHA-256。必须在上传前立即取得用户明确同意。
9. 只有取得同意后，才用相同命令加上 `--confirmed` 重新执行。报告返回的项目、修订版、slug 和审核状态。

更新项目时先运行 `projects`，按 ID 和 slug 匹配已有项目。只有确认目标后才使用 `submit --project-id <id>`。不要因为更新失败就创建第二个项目。

## 先展示玩法的文案规则

公开文案面向想选择有趣体验的用户，而不是硬件设计评审：

- 说明应用把 AI Passport 变成什么、用户如何开始或游玩，以及体验为什么有趣、意外、适合社交、有用或令人愉快。
- 标题中写出玩法或应用名称，不要写开发板、芯片、元件、框架或硬件方案。
- 描述必须建立在项目可验证的行为上。优先采用“它是什么、怎么玩、为什么值得尝试”的简单流程。
- 需要确认固件时可以阅读技术文件，但不得把实现细节带入公开标题或描述。
- 排除芯片和开发板名称、厂商、音频编解码器、显示控制器或规格、总线、引脚、内存和 Flash 容量、分区、SDK、框架、构建系统及类似工程术语。公开文案不得出现 `ESP32`、`ESP32-C3`、`ESP32-S3`、`Espressif`、`乐鑫`、`ES8311`、`I2C`、`I2S`、`SPI`、`UART`、`GPIO`、`OLED`、`LCD`、`LVGL` 以及屏幕型号或分辨率等示例术语。
- 如果仓库主要是技术内容，应从使用步骤、截图、演示视频、素材、界面文字和运行时行为中提炼体验。只有无法避免猜测时，才向创作者询问缺失的玩法信息。
- 英文版本应是自然的产品文案，与中文含义和语气一致，不要逐字翻译。

展示投稿预览前，重新阅读两种描述，把技术规格改写成用户可感知的好处或交互。不能只删除术语而留下含糊或残缺的句子。例如把“基于 ESP32-S3、ES8311 和 2.4 英寸屏幕的离线互动播放器”改写为“把 AI Passport 变成随身互动播放器，点开角色就能重温经典片段，适合聚会时和朋友一起玩”。

## 边界

- 除非创作者明确要求开发服务器，只能上传到 `https://ai-passport.folotoy.cn`。覆盖地址使用 `FOLOTOY_AI_PASSPORT_URL`。
- 固件必须是非空的 ESP 合并镜像且不超过 8 MiB。封面必须是严格 3:4 的 JPEG、PNG 或 WebP 且不超过 10 MiB。提供源码时必须是公开 HTTPS Git 仓库项目页面，不得使用本地路径或携带凭据的 URL。
- 通过本工具发布必须有最近一次成功的 `FAP_SCREENSHOT_V1` 串口捕获及其匹配回执。仓库截图或手动提供的图片不能替代该连接证明。
- 授权只授予投稿权限。凭据存放在项目外且仅所有者可读；绝不打印、提交或复制令牌到源码文件。
- 发布和更新属于外部变更。校验、起草和预览不等于授权上传。
- 不得批准审核、伪造互动数据或绕过服务器校验。

只有在排查授权或服务器响应时才阅读 [references/api.md](references/api.md)。
